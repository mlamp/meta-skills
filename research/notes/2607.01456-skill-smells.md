# From Anatomy to Smells: An Empirical Study of SKILL.md in Agent Skills

- arXiv:2607.01456v2 [cs.SE] · Hong, Imani, Ahmed (UC Irvine) · 2026-07-03 · retrieved 2026-07-21
- https://arxiv.org/abs/2607.01456
- One line: first large-scale study of SKILL.md as a software artifact — component taxonomy, 26 community best practices inverted into 26 "skill smells", an automated detector, prevalence and evolution numbers.

## What they did

- 238 real SKILL.md files: skills.sh marketplace dump (133k skills) → English, ≥10 weekly downloads, top decile by repo stars, one skill per repo.
- Two-author qualitative coding of H2-level sections → taxonomy of 13 higher / 44 lower semantic components.
- Multivocal literature review: top-50 web sources on agent-skills best practices → 29 kept → 26 best practices (conflicts settled by majority vote). Smell = inverted best practice.
- Detector (SSD): 5 smells statically (scripts), 21 via LLM judge (Qwen3.6-27B, 4-bit AWQ, thinking mode; per-smell definition + one positive + one negative example, binary yes/no). Ground truth: 53 hand-labeled files. Weighted F1 0.78, precision 0.79, recall 0.78.
- Evolution: 1,295 commits across 142 multi-commit skills, weekly prevalence Oct 2025 – Jun 2026.

## Numbers that matter

- >99% of skills have ≥1 smell; average 10.5 smells per skill; 11 of 26 smells appear in >50% of files; 1 of 238 files is clean.
- Most prevalent smell: Rationalization Loophole — 94% of files.
- Component prevalence: Task 74%, Introduction 64%, References 57%, Principles 42%, Usecase 33%, Context 28%, Output Format 24%, Practice 23%, Evaluation 21%, rest <5%.
- Only 7 of 13 higher-level components have any explicit community guidance. Introduction, Evaluation, Tools, MCP Integration, Agent Architecture, Other have none.
- Smells rarely disappear once introduced; prevalence mostly grows over a skill's lifetime.

## The 26 smells (rubric raw material)

Under-specified guidance:
- TSW Stepless Workflow — whole workflow as one prose block, not decomposed into steps.
- TOB Option Buffet — multiple tools/libraries offered, no default recommended.
- MDT Missing Decision Tree — no guidance for choosing between approaches by situation.
- MUS Missing Utility Script — script-worthy work left for the agent to improvise.

Over-prescribed guidance:
- SOC Series of Commands — rigid line-by-line commands with hardcoded paths/args instead of the objective.

Missing verification & feedback:
- NVS No Validation Step — output treated as one-shot, no validation loop.
- EWP Execute Without a Plan — complex tasks with no planning or validation stage.
- NAH Never Asks Human — no mechanism to request human feedback.

Missing follow-through guards:
- RL Rationalization Loophole — nothing discourages rationalizing or skipping required steps.
- NPT No Progress Tracking — multi-step workflow with no progress mechanism.

Context bloat:
- UD Undelegated Detail — low-level detail not delegated to references or scripts.
- LSB Lengthy Skill Body — body over 5,000 words.
- LSN Lengthy Skill Name — name over 64 characters.
- LSD Lengthy Skill Description — description over 1,024 characters.
- CSD Confusing Skill Description — description missing [what it does] + [when to use] + [keywords].

Missing safeguards:
- NG No Guardrails — nothing prevents inappropriate or impossible attempts.
- BG Buried Gotchas — critical warnings not highlighted with gotcha headers.
- MUR Missing Usage Rules — no rules governing when or how the skill applies.
- MC Missing Caveats — common caveats and their resolution omitted.

Inadequate grounding:
- ME Missing Example — no examples to anchor sufficient context.
- TSS Time Sensitive Skill — content that goes stale unless the agent knows the current date.

Security:
- XID XML Included Description — XML tags in frontmatter description can inject instructions.

Convention & style:
- BP Backslash Path — backslash paths; skill paths need forward slashes.
- USN Unclear Skill Name — name doesn't convey capability or action.
- NTPD Non Third Person Description — description not in third person; hurts discovery.

Unstructured output:
- MT Missing Template — output needs a specific format but no template is given.

## Component taxonomy (structural vocabulary)

Task (steps, subtasks, error handling, environment variation) · Introduction (prerequisites, trigger, summary, quick start, directory format, auth) · References (reference files, commands, domain knowledge, tips, related skills, utility scripts, standards) · Principles (rules, generation quality, instruction hierarchy) · Usecase (common patterns, examples) · Context (ambiguity handling, decision tree, target system, guardrail conditions, persona) · Output Format (return artifact, lessons learned, procedural docs) · Practice (best practices, anti-patterns) · Evaluation (review checklist, running tests, debugging) · Tools · MCP Integration · Agent Architecture (composition, model choice) · Other.

## Use for skill #1

- The smell catalog is a ready rubric skeleton. The five static smells (LSB, LSN, LSD word/char caps; BP; XID) are grep/script checks; the rest are judge checks — keep that split.
- Their judge framing is copyable: per-smell definition + positive + negative example, binary answer, thinking mode.
- Their F1 0.78 on 53 labeled files is the bar our detector should beat, measured the same way on our fixtures.
- The [what/when/keywords] description rule doubles as a trigger-quality check (C04).

## Caveats — why this stays unproven

- "Best practices" are community folklore from 29 web sources, majority-voted — not causally validated. The paper shows smells are prevalent, not that they are harmful.
- Sample skews to popular public marketplace skills; our targets may differ.
- Detector numbers rest on 53 labeled files and one quantized open model.
