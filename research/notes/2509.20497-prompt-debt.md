# PromptDebt: A Comprehensive Study of Technical Debt Across LLM Projects

- arXiv:2509.20497v1 [cs.SE] · Aljohani, Do (Univ. of North Texas) · 2025-09-24 · retrieved 2026-07-21
- https://arxiv.org/abs/2509.20497
- One line: mined 93k Python files that use LLM APIs for self-admitted technical debt (TODO/FIXME comments); prompts are the main LLM-specific debt source, and instruction-style prompt text is the most debt-prone.

## What they did

- PromptSet dataset → 91,377 relevant Python files → 340,840 cleaned comments → 6,042 SATD comments (1.77%).
- 998-comment stratified sample manually classified into LLM-specific debt types (two raters, Cohen's kappa 0.74).
- 155 developer-written prompts classified by prompt technique to see which techniques attract debt.

## Numbers that matter

- LLM-specific SATD in the sample: Prompt Debt 6.6%, Hyperparameter Debt 4.5%, Framework Debt 4.3%, Cost Debt 2.1%, Learning Debt 0.6%.
- By technique: instruction-block prompts carry 38.6% of prompt-technique SATD (clarity and length problems); few-shot 18.1% (placeholder/dummy examples never replaced); documentation prompts 12.3% (oversized pasted context).
- Recurring debt shapes: missing prompt templates, hardcoded values inside prompts, postponed output-format handling ("TODO: turn response to JSON"), postponed cost handling.

## Use for skill #1

- Skills are instruction-heavy prompt artifacts — exactly the most debt-prone category. Review weight goes to instruction clarity and length first (C08).
- "Placeholder example" is a concrete, checkable finding: examples must be real and task-specific (C09).
- Debt gets deferred and accumulates silently — an argument for periodic re-review of skills, not one-shot review.

## Caveats — why this stays unproven

- Studies Python API code and its comments, not SKILL.md files; transfer to skills is our assumption to test.
- SATD only captures debt developers admitted in comments; silent debt is invisible to the method.
- Technique-level numbers rest on 155 prompts — small.
